## 1. 已验（可复现）

### 1.1 门禁

`make photobench-web-check` 四步全绿：`tsc -b --force` / `oxlint`（0 warning）/ `vitest`
（**445 条**）/ `vite build`。全量 `make ci` 里的其余步骤在本轮之前已验过（S10a 收口）。
后端不受影响：`apps/photobench` 的 408 条与 `apps/api` 的用例未改动。

### 1.2 端到端起来了（真机）

```
2.0 前端 4276  ← vite proxy →  9597（2.0 PhotoBench 后端）→ 1.0 的 results/
```

| 探活 | 结果 |
|---|---|
| `GET http://127.0.0.1:4276/` | 200 |
| `GET http://127.0.0.1:4276/api/runs`（**经 vite proxy**） | 168 个 run（扫的是 1.0 的 `results/`） |
| `GET http://127.0.0.1:4276/api/manifests` | `album3` / `album3-14` / `album3-kling` / `album3-max` / `album3-max-video10` |

**1.0 的同一条链也在跑**：前端 5173、后端 8771。所以两个界面可以并排开。

### 1.3 class 名双向差集（结构保真度）

`scripts/check_photobench_web_classes.py`：把 1.0 模板用到的类名与 2.0 组件用到的
双向求差，两边都用 1.0 `styles.css` 里**真实存在的类名集**过滤。

```
1.0 模板用到 351 个真实类名
2.0 组件用到 348 个真实类名
交集 347 个
只在 2.0 出现：1 个（interrupted）—— 假阳性：它是状态字符串，不是 class
只在 1.0 出现：1 个（metric）    —— 假阳性：它是变量名
```

**结论：自造 0 个、漏掉 0 个。** 347 个共用类名一个不差。

**这个脚本自己也被纠正过一次**，值得记：v1 按「静态 `class="…"` 属性」提取，
而 2.0 大量用模板字面量（`` `qa-item${open ? " open" : ""}` ``），于是 v1 报出
24 个「只在 1.0 出现」——抽查的 11 个**全是提取漏的**。v2 改成双向对称（抓所有引号字符串）
+ CSS 类名集过滤，才得到上面这个干净的结论。

### 1.4 样式

`src/styles/photobench.css` 是 1.0 `styles.css` 的**逐行移植**，选择器名一字未改，
只删了 `.arbiter-*` 那 5 行（死面板）。

## 2. 未验（留给你）

**视觉与交互的逐面板等价性，我没有验过。** 没有 headless 浏览器，我无法渲染、
无法截图、也无法模拟点击。以下这些属于你的对照范围：

- 各面板的**布局与观感**（CSS 是同一份，但 DOM 结构由重写决定，class 相同不等于
  DOM 层级相同）；
- **交互**：切 tab、展开/折叠、分页、筛选、删除确认、导出下载、弹窗；
- **需要真数据才看得出的东西**：选一个 run，逐块看详情（记忆层级树、命中矩阵、
  关键帧 8 格、遥测图、QA 逐题展开）。
